2、云服务器去搭建中间件

3、下载并上传Web程序源码（如z-blog）

  并绑定域名目录

如果子域名的源码不一样，漏洞也不一样

2、Web其他-集成软件&Docker容器&分配站等

（可以用Docker镜像一个网站，注册网站后可以申请一个网站来使用–分配站）

（大域名给你一个小网站使用，在测试小网站时，干的是一个大网站–更安全）

（如宝塔，phpstudy，宝塔会将中间件 数据库 源码 给弄好，这叫集成软件）

（以上偏个人，而大公司有自己的服务器，搭建东西有区别，用途也不同，源码会不同）

web程序源码：开源：商业自写，打自己的博客，免费；但功能不足。

闭源：花钱，专人来写，商业用途。

用挖洞工具，一开始就知道源码能不能拿到手，知道目标路径，判断难易，构建不同思路。

解析访问：如得到网站权限（留了网站后门）–用哥斯拉链接后门访问。

如何防备？在右键编辑权限-安全中：

发现访问时无权限。系统管理员可以修改权限，如读取，写入。（脚本运行需要权限）

但不能用，（用于锁图片权限–它只用看，不用执行）会导致网站不能正确运行。

（后期做安全测试，可能会遇到的问题）（更改所有者为Everyone ？）

身份验证：

发现需要登陆认证。（一般学校网站需要登陆认证）且不能绕过，只能用管理账号

这些配置都会影响安全测试。

数据库：（使用Access）

根据名字，单词意思找路径，用户，密码……

该数据库有个特点：像表格形式，用office可以打开，可以看到后台管理员账号密码，各种数据

而MSSQL会让写数据库主机，用户名与密码。

站库分离：

网站源码与数据库不在一起。（不一定所有网站都支持）

在数据库配置文件（如app.config）中：

value=1，指用MSSQL，user id=，password=，……看到，source后的IP与本机不同，实现站库分离。

删除数据库，网站没了（删库跑路了doge）

传统：数据库在操作系统运行

现在：厂商可以提供云数据库

如果，数据库在本地，能拿到权限的话，本地数据全能拿到；现在数据库在另一个服务器，就不一定能行，数据库外联特性与绑定特性，拿到权限也不一定拿到数据；云服务器更安全，登陆方式有限制，不使用账号密码，甚至限制IP登陆。放到OSS（存储数据的）也是一样道理。传统在上传文件会给到数据库，利用后门拿到数据，现在文件上传到OSS中，没用。（没有解析后门代码的，仅存储）

漏洞都是传统，用云，OSS，等于没有漏洞。

后期信息收集，就是判断漏洞类型。

绝对相对路径：

对于源码，分：

开源-源码可见

开源-源码不可见：加密：例如asp代码加密，PHP代码加密–不会影响功能，但会显示乱码

​ 语言特性决定：如JAVA，也会显示乱码

白盒测试-代码审计 代码反编译

路由访问

常规：访问某文件，网站/post/1.txt –URL与文件目录对应上

路由访问：mvc源码 java python 常用，有的可以打开，有的打不开（而且就这个目录下文件访问不上）（尽管文件存在，但必须由特定路由规则才可以访问）–URL与文件目录对应不上，要由配置路由决定

所以后期写开发，写路由的配置，看源码分析漏洞就知道漏洞解决方法，地址怎么构造

（配置服务器：上网搜）

解析规则：

MIME类型：（网站访问图片，展示图片，访问文本，却下载文本，就是由它决定）

如.avi是视频等。网站访问图片，展示图片，访问文本，却下载文本，就是由这个中间件上面配置决定，如果修改，会乱。
